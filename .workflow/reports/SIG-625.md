# Implementation Report — SIG-625

## Changes
- `contracts/modules/TradeModule.sol`
  Added `_resolvePositionOwner(positionId)` so direct owners and ERC721-approved operators both satisfy lifecycle auth. `increasePosition`, `_decreasePositionInternal`, and `_processClaimPayout` now resolve the actual NFT owner once and use that owner for fee-policy trader attribution and lifecycle event emission, while keeping all payment pulls/pushes on `msg.sender`.
- `contracts/router/SignalsRouter.sol`
  Removed the lifecycle custody pattern. `increasePositionWithSwap`, `decreasePositionWithSwap`, `closePositionWithSwap`, and `claimPayoutWithSwap` now require `positionNFT.ownerOf(positionId) == msg.sender` up front and call Core directly as the approved operator, without taking and returning the NFT. The stale header comment about router-observed traders was removed.
- `contracts/testonly/MockTraderFeePolicy.sol`
  Added a fee policy test double that returns different fees based on `params.trader`, so the tests can prove TradeModule passes the real owner into fee-policy quoting.
- `test/foundry/integration/trade/ApprovedOperator.t.sol`
  Added regression coverage for `setApprovalForAll` and `approve` operator flows across increase, decrease, claim, and batch claim, including fee-policy trader attribution and event trader attribution.
- `test/foundry/e2e/router/SignalsRouter.t.sol`
  Added router-specific regression coverage for explicit caller-owner checks and for the absence of router-address `Transfer` logs during lifecycle operations.
- `test/foundry/e2e/core/SponsoredPosition.t.sol`
  Added a sponsored winning-claim regression that proves an approved operator receives the user-profit portion while the sponsor still receives principal, and that events still identify the beneficiary as trader.

## Design Decisions
- Resolved the owner inside `TradeModule` rather than in `SignalsCore`, because the ownership check, fee-policy quote, and event emission all live in the module. That keeps the authorization/trader logic colocated with the effects it governs.
- Returned the resolved owner from `_decreasePositionInternal` instead of resolving twice. That avoids a redundant `ownerOf`/approval lookup and keeps the event emission in `decreasePosition` and `closePosition` consistent with the fee-policy call inside the shared helper.
- Kept all token movements on `msg.sender` even when the event trader is the NFT owner. That preserves router-mediated ctUSD custody for swap in/out and matches the plan’s requirement for sponsored payout routing.
- Used the shared `SE.UnauthorizedCaller` error in `SignalsRouter` for the new caller-owner guard so router failures and core failures stay consistent in tests and in downstream handling.

## Known Tradeoffs
- The new auth helper accepts both `getApproved` and `isApprovedForAll`, which is the intended ERC721 behavior, but it also means per-token approvals now persist across router lifecycle calls because those calls no longer clear approval via transfer. That is standard ERC721 semantics, but it is a behavioral change relative to the old custody workaround.
- The router owner guard is duplicated across the lifecycle entrypoints through a shared helper. That keeps the router change local and explicit, but the core-level auth still remains the real source of truth for approved-operator execution.
