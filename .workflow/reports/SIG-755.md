# SIG-755 — v1-contract: multi-asset oracle infrastructure + scripts + deploy-config

## Summary
Jira summary: "v1-contract: multi-asset oracle infrastructure + scripts + deploy-config". This changes v1-contract from global Redstone asset config to per-market oracle config while keeping BTC-only operation unchanged. The PR appends `feedId`, `feedDecimals`, and `tickScale` to `Market`, adds `MarketOracleConfig` to `createMarket`, centralizes price-to-tick conversion in `OracleTickLib`, zombifies the old global feed storage, adds `reinitializeV2()` for BTC backfill, and updates scripts, deploy config, Safe upgrade planning, fork tooling, storage snapshots, ABI exports, and tests.

## Changes
- `contracts/interfaces/ISignalsCore.sol`: appended per-market oracle fields to `Market`, added `MarketOracleConfig`, and updated `createMarket` / `setRedstoneConfig` ABI surface.
- `contracts/core/SignalsCore.sol` and `contracts/core/SignalsCoreStorage.sol`: removed global feed init writes, renamed global feed storage to private deprecated slots with OZ rename annotations, added `OracleConfigBackfilled`, added `reinitializeV2()`, and delegated the new `createMarket` / slim `setRedstoneConfig` signatures.
- `contracts/modules/MarketLifecycleModule.sol` and `contracts/modules/OracleModule.sol`: validate/store per-market oracle config, emit expanded `MarketCreated`, read per-market feed settings in Redstone submission, and use `OracleTickLib` for settlement tick conversion.
- `contracts/lib/OracleTickLib.sol` and `contracts/testonly/OracleTickLibHarness.sol`: added the shared division-first settlement tick conversion and a harness for parity/fuzz tests.
- `script/`, `scripts/`, and `script/config/`: removed active global feed config keys, updated market creation/close scripts for `tickScale`, updated fork calldata generation to read `getMarket`, and changed Safe upgrade preparation/proposal flow to MultiSend with operation support and simulation handling.
- `test/foundry/`: updated helpers and direct struct literals for the new market layout, added oracle-config validation/missing-config tests, reinitializer/backfill coverage, fork upgrade setup, and `OracleTickLib` parity/fuzz coverage.
- Finish pass fix: `test/foundry/fork/base/ForkBaseTest.sol` now repairs the local dev fork snapshot when processed batch flags are ahead of `currentBatchId`; `ForkProtocolTest` now finalizes already-failed ambient markets directly. This fixes live dev fork drift without changing production contracts.

## Design Decisions
- D1/D2: `Market` fields are appended only, and `MarketOracleConfig` lives beside `Market` in `ISignalsCore` so every module and ABI consumer shares one type definition.
- D3: `OracleTickLib.toSettlementTick(Market storage, int256)` keeps the old division-first BTC behavior and swaps the hard-coded `1_000_000` divisor for `market.tickScale`.
- D4/D5: `reinitializeV2()` is on `SignalsCore` with `reinitializer(2) onlyOwner` and hard-coded BTC defaults, because upgrade-time backfill belongs in the initialized storage owner and has no runtime asset choice.
- D6/D7: `redstoneFeedId` and `redstoneFeedDecimals` remain in their original slots as private `__deprecated_*` zombies with `@custom:oz-renamed-from`, removing automatic ABI views while preserving layout.
- D8/D11: `createMarket` performs minimal oracle config validation, while submit/finalize paths use explicit `OracleConfigMissing(marketId)` guards before tick conversion.
- D9: `setRedstoneConfig` is retained but slimmed to protocol-level timing values only: `maxSampleDistance` and `futureTolerance`.
- D10: v1-contract exports regenerated ABIs as the source of truth for sibling repo inline ABI updates; sibling repo edits remain out of this issue scope.
- D12: `ISignalsCore.createMarket` keeps calldata in the interface, `SignalsCore.createMarket` uses memory so existing harness internal calls continue to work, and `MarketLifecycleModule` receives calldata through delegatecall.

## Known Tradeoffs
The dev fork helper uses hard-coded storage slots for `currentBatchId` and `_batchAggregations` because the public dev fork currently has processed batch flags ahead of `currentBatchId`. This is test-only fork repair logic and is bounded to the dev fork setup.

No production shortcut was taken in the contract path. Multi-asset operation remains intentionally unavailable until a future per-market oracle-config setter/cutover issue.
