# Implementation Report — SIG-755

## Changes
Jira summary: "v1-contract: multi-asset oracle infrastructure + scripts + deploy-config". Jira status during this round was "Changes Requested". The issue description covers the SIG-740 contract-track migration from global Redstone asset config to per-market oracle config, with BTC-only operations preserved.

- `test/foundry/unit/lib/OracleTickLib.t.sol`: added `test_zeroTickScaleCausesEvmPanic`, documenting that `OracleTickLib` intentionally relies on caller-side `tickScale` guards and otherwise panics on division by zero.
- No changes made to `contracts/lib/OracleTickLib.sol`: the review directive explicitly required no library guard because production callers can emit the more precise `OracleConfigMissing(marketId)` error.
- No changes made to `script/ops/CreateMarket.s.sol` or `script/config/market-template.json`: the BTC hard-coded oracle config is intentional per the SIG-755 plan and the review directive's rebuttal section.

## Design Decisions
The added test uses `vm.expectRevert()` without a selector, matching the directive and the actual EVM panic behavior for division by zero. I kept this as a unit-level invariant rather than a production guard so the contract design remains caller-owned: `submitSettlementSample`, `finalizePrimarySettlement`, and `finalizeSecondarySettlement` are responsible for checking `tickScale` before entering the shared conversion library.

I placed the test next to the existing BTC parity, custom scale, and fuzz coverage because it documents the boundary condition of the same conversion primitive without broadening the diff or touching operational scripts.

## Known Tradeoffs
None for this targeted round. The new coverage documents an unsafe direct library call path, but intentionally does not make the library self-validating because the library does not know `marketId` and would produce a weaker error surface than the guarded production call sites.
