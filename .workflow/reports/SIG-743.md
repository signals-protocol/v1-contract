# Implementation Report — SIG-743

## Jira Context
Summary: Storage layout diff CI tooling for upgrade safety.

Description: v1-contract lacked CI tooling to compare `forge inspect storageLayout` output against a committed baseline. The issue exists because UUPS storage layout violations can corrupt proxy storage, and upcoming storage rename/struct extension work needs automated checks for slot/type/offset changes, allowed OZ rename annotations, struct member reorders, and append-only changes.

## Changes
- `scripts/storage-layout/types.ts`: removed the redundant `name` property from `TrackedContract`; `contractName` is now the single display/identity field for tracked contract names.
- `scripts/storage-layout/config.ts`: removed duplicate `name` entries from the three tracked UUPS contract definitions.
- `scripts/storage-layout/index.ts`: replaced all tracked-contract map keys and user-facing messages that used `contract.name` with `contract.contractName`.
- `scripts/storage-layout/__tests__/storage-layout.test.ts`: updated tracked-contract fixtures to the new shape and added a reverse UUPS drift test for a tracked FQN that is no longer discovered as a non-testonly UUPS contract.

## Design Decisions
I kept `contractName` as the only short contract label because it is already explicit enough for log messages, map keys, and comparator labels. The FQN remains available when the tool needs path-qualified identity, so reintroducing a second short name would only recreate the ambiguity the directive called out.

The new reverse drift test isolates that direction by building a fixture with no discovered non-testonly UUPS contract matching the tracked FQN. That keeps the assertion focused on the explicit reverse-check failure message instead of also exercising the forward "untracked discovered UUPS" path.

## Known Tradeoffs
No functional tradeoffs. `currentLayouts` is still keyed by `contractName`, which is acceptable for the current tracked set because contract names are unique and the FQN remains on the tracked entry for forge inspect and UUPS validation.
