# Implementation Report — SIG-743

## Issue Context
- Summary: Storage layout diff CI tooling for upgrade safety
- Description: v1-contract lacked an automated CI gate for `forge inspect storageLayout` baselines. UUPS storage layout violations can corrupt proxy state, and upcoming tasks need automated coverage for label renames with `@custom:oz-renamed-from` and struct append safety.

## Changes
- `scripts/storage-layout/config.ts`
  Defines the tracked UUPS contract FQNs in one place: `SignalsCore`, `SignalsPosition`, and `SignalsLPShare`.
- `scripts/storage-layout/types.ts`
  Adds minimal TypeScript types for Foundry storage-layout JSON and tracked contract metadata.
- `scripts/storage-layout/comparator.ts`
  Adds canonical layout reduction and semantic safety comparison. It ignores `astId`, uses `types[*].label` for canonical type identity, recursively follows reachable struct types through mappings/arrays/members, permits prefix-only struct appends, permits annotated renames, rejects slot/offset/type changes, and conservatively rejects top-level packing into an existing slot.
- `scripts/storage-layout/build-info.ts`
  Adds AST-backed annotation lookup. It filters build-info candidates by exact storageLayout equality, then by source-content equality against the working tree before resolving `astId` documentation. It also adds an AST-based UUPS drift check that excludes `contracts/testonly/**`.
- `scripts/storage-layout/index.ts`
  Adds `snapshot` and `check` commands. `snapshot` writes raw forge layouts to `storage-snapshots/`. `check` runs current `forge inspect`, validates tracked UUPS drift, compares against `origin/main` snapshots for safety when available, and enforces committed snapshot freshness through canonical strict equality.
- `scripts/storage-layout/__tests__/storage-layout.test.ts`
  Adds fixture-based unit coverage for identity, appends, forbidden slot/offset/type changes, annotated and unannotated renames, struct reorder/type changes, astId/type-id canonicalization, nested mapping-to-struct traversal, stale-vs-safety separation, and build-info disambiguation.
- `storage-snapshots/SignalsCore.json`, `storage-snapshots/SignalsPosition.json`, `storage-snapshots/SignalsLPShare.json`
  Adds initial raw `forge inspect <FQN> storageLayout --json` baselines for the current layouts.
- `package.json`
  Adds `storage:snapshot`, `storage:check`, and `storage:test` scripts.
- `.github/workflows/ci.yml`
  Uses `fetch-depth: 0`, then runs `yarn storage:test` and strict `yarn storage:check` after `forge build` and before `forge test`.

## Design Decisions
- I kept raw Forge JSON as the committed review artifact, but reduced both snapshots and current layouts into a canonical semantic form before comparing. That removes compiler-context noise from `astId` and type identifier AST numbers without hiding real storage changes.
- I split safety and freshness checks deliberately. Safety uses base-branch snapshots and allows only storage-safe changes; stale checking uses the PR snapshot and requires exact canonical equality so intentional layout changes still have to update `storage-snapshots/` in the same PR.
- Annotation lookup is build-info based rather than source grep. The source-content filter matters because a stale build-info file can have the same storage layout while differing only in NatSpec annotations.
- Top-level additions are stricter than struct additions. New top-level fields must use slots after the previous terminal slot; struct additions may append at the end of the member list because struct packing is part of the struct definition and the prefix check protects existing members.
- The UUPS drift check is AST based so a new non-testonly UUPS contract cannot be silently left out of the tracked list.

## Known Tradeoffs
- The tool covers own storage from `forge inspect storageLayout`. It does not validate ERC-7201 namespaced storage used by OZ upgradeable bases.
- `__gap` shrink plus new variable patterns are intentionally not supported. That future case should get a focused extension rather than weakening this conservative comparator.
- The first SIG-743 rollout cannot compare against base snapshots because `origin/main` does not have `storage-snapshots/` yet. The check warns and still enforces snapshot freshness; after this merges, base-branch safety becomes active automatically.
