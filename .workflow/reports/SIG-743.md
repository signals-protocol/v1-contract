# Implementation Report — SIG-743

## Changes
- `scripts/storage-layout/build-info.ts`
  Added process-local memoization inside `loadBuildInfos(root)` so all annotation resolution and UUPS discovery share one parsed build-info array per repo root. Also tightened the untracked UUPS validation error to explicitly tell maintainers to add the discovered FQN to the tracked storage list.
- `scripts/storage-layout/__tests__/storage-layout.test.ts`
  Added fixture-based coverage for UUPS drift detection: direct UUPS inheritance, transitive UUPS inheritance, `contracts/testonly/**` exclusion, validation success when discovered contracts are tracked, and validation failure when a non-testonly UUPS contract is missing from the tracked list.
- `scripts/storage-layout/index.ts`
  Changed `forge inspect` execution to pipe stderr instead of inheriting it. Successful inspections now keep CI storage-check logs clean; failed inspections include captured stderr/stdout in the thrown failure.
- `scripts/storage-layout/comparator.ts`
  Documented the conservative top-level append rule that rejects `__gap` shrink plus in-gap variable insertion patterns.

## Design Decisions
- I kept memoization inside the build-info module rather than changing constructor or function signatures. That preserves the current call sites and keeps the optimization shared by both `BuildInfoAnnotationResolver` and `discoverUupsContracts`.
- The UUPS tests synthesize minimal build-info AST JSON in the existing test file instead of adding heavier fixture files. The discovery logic only needs source paths, contract names, ids, and `linearizedBaseContracts`, so the fixtures stay focused on the regression surface.
- The forge wrapper captures both stderr and stdout on failure because some toolchain errors split diagnostics across streams. On success both streams are discarded except for parsed JSON stdout, which prevents warnings from interleaving with `[storage:check]` status lines.

## Known Tradeoffs
- The in-memory build-info cache is process lifetime only, by design. A long-running process that mutates `out/build-info` after the first load would need a new process to observe those changes; the storage scripts run as short-lived CLI processes.
- The `__gap` behavior is documentation-only in this round. The comparator already rejects the unsafe pattern through existing slot/type checks plus the top-level append rule.
